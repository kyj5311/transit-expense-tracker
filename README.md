# 대중교통 사용 내역 관리 앱

대중교통(지하철·버스) 이용 시 후불 교통카드만으로는 파악하기 어려운 세부 지출 내역을
직접 등록·관리하고, 기간별 지불 금액을 계산해볼 수 있는 웹 앱입니다.
서버·데이터베이스 없이 브라우저만으로 동작합니다.

자세한 요구사항과 설계 근거는 [docs/03_설계서](docs/03_설계서)의 소프트웨어 설계서(v1.6)를 참고하세요.

## 특징 / 제약사항

- 순수 HTML/CSS/JavaScript(ES6)로만 작성 — 외부 라이브러리, 빌드 도구 없음
- 서버·DB 없음 — 브라우저 **LocalStorage**에만 데이터를 저장 (`fareData` / `templateData` / `logData` 3개 키)
- `index.html`을 더블클릭해서 여는 것만으로 실행 가능 (인터넷 연결·설치 불필요)
- 회원가입/로그인, 다중 사용자, 외부 결제 연동은 범위 밖

## 실행 방법

1. 이 폴더를 통째로 다운로드/클론한다.
2. `index.html`을 Chrome, Edge 등 브라우저로 더블클릭해서 연다.
3. 최초 실행 시 기본 요금 데이터(서울/대구)가 자동으로 LocalStorage에 저장된다.

## 사용 방법

앱은 상단 탭 4개로 구성된다: **대시보드 / 템플릿 등록 / 사용 내역 / 지불 계산**

### 1) 템플릿 등록

자주 쓰는 노선을 미리 등록해두고 재사용하기 위한 화면이다.

1. 노선명을 입력하고(예: `대구 3호선`), 교통수단 · 지역 · 요금등급 · 환승 여부를 선택한 뒤
   **[구간 추가]**를 누른다. 하나의 템플릿에 구간을 여러 개 담을 수 있다(예: 지하철 구간 +
   환승 버스 구간).
2. 구간을 원하는 만큼 추가했으면, 템플릿 이름을 입력하고(예: `출근길`) **[템플릿으로 저장]**을
   누른다.
3. 등록된 템플릿은 아래 "등록된 템플릿 목록"에 구간 수와 함께 나타난다.
   - **[내역등록]**: 그 템플릿의 구간 수만큼 "사용 내역"에 한 번에 등록한다.
   - **[삭제]**: 템플릿을 목록에서 삭제한다.

### 2) 사용 내역

실제로 등록된(또는 템플릿으로 일괄 등록된) 사용 내역을 조회·관리하는 화면이다.

- 상단 **조회** 드롭다운으로 전체 / 이번 달 내역만 볼 수 있다.
- 각 행의 **[수정]**을 누르면 그 줄만 바로 편집 가능한 입력창으로 바뀐다(노선명/구분/환승
  여부만 수정 가능). **[저장]**/**[취소]**로 마무리한다.
- **[삭제]**로 개별 내역을 지운다.
- 체크박스로 원하는 내역만 고른 뒤 **[선택한 내역만 지불 계산하기]**를 누르면 지불 계산
  화면으로 이동해 그 내역들만 기준으로 계산한다.

### 3) 지불 계산

- 조회 단위(**이번 달** / **전체**)를 고르고 **[계산하기]**를 누르면 총 지불 금액과, 내역별
  기본요금·환승 할인 적용 여부·실제 금액이 상세 표로 나온다.
- 사용 내역 화면에서 "선택한 내역만" 계산하도록 넘어온 경우, 안내 문구와 함께 그 내역들
  기준으로 자동 계산된다. 다시 조회 단위 기준으로 보려면 **[계산하기]**를 한 번 더 누른다.
- 계산 대상 내역이 0건이면 0원으로 표시된다.

### 4) 대시보드

앱을 열면 처음 보이는 화면. 이번 달 총 지불 금액, 등록된 템플릿 수, 이번 달 사용 내역
건수, 최근 내역 5건을 한눈에 보여준다.

## 폴더 구조

```
index.html          UI-01~04 화면 마크업 + 탭 구조
style.css            전체 스타일시트
js/
  storageModule.js    LocalStorage 저장/로드 공통 처리 (save/load)
  fareModule.js        지역·교통수단·요금등급별 기본 요금 + 환승 할인율 관리
  templateModule.js    노선 템플릿 등록/조회/삭제
  logModule.js          사용 내역 등록(템플릿 기반/직접)/수정/삭제
  paymentCalcModule.js  선택된 내역의 총 지불 금액 계산
  uiModule.js            화면 렌더링 + 이벤트 바인딩 (다른 모든 모듈을 사용)
dev-seed/
  daegu-kumoh-templates.js   개발/테스트용 더미 템플릿 시드 스크립트 (앱에는 연결 안 됨)
docs/
  01_제안요청서/ 02_제안서/ 03_설계서/   과제 산출물(PDF/HWP) 보관
```

`index.html`의 `<script>` 태그는 의존 관계 순서를 따른다 — `storageModule.js`가 항상
제일 먼저, 나머지 모듈이 전부 사용하는 `uiModule.js`가 제일 마지막에 로드된다.

## 모듈 구조 (설계서 4.1 기준)

| 모듈 | 파일 | 책임 |
|---|---|---|
| StorageModule | `js/storageModule.js` | `save(key, data)` / `load(key)` — LocalStorage 저장·로드를 try-catch로 감싸 공통 처리 |
| FareModule | `js/fareModule.js` | 지역별 기본 요금·환승 할인율(TransferDC) 관리, 앱 최초 실행 시 기본값 시드 |
| TemplateModule | `js/templateModule.js` | 노선 템플릿 등록(`addTemplate`)/조회/삭제 |
| LogModule | `js/logModule.js` | 템플릿 기반 일괄 등록(`addLogFromTemplate`)/직접 등록/수정/삭제 |
| PaymentCalcModule | `js/paymentCalcModule.js` | `calculatePayment(targetLogs, fareData)` — 내역 배열을 받아 총 지불 금액 계산 |
| UIModule | `js/uiModule.js` | 화면 렌더링, 이벤트 바인딩. 계산·저장 로직은 갖지 않고 다른 모듈만 호출 |

함수는 모듈 객체(`TemplateModule.addTemplate(...)`) 없이 전역 함수로 되어 있다 — 설계서
6.2의 함수 시그니처(`calculatePayment(targetLogs, fareData)`, `addLogFromTemplate(templateName)`,
`save(key, data)` / `load(key)` 등)를 그대로 호출할 수 있게 하기 위함이다. 여러 `<script>`
파일은 로드 순서만 지키면 서로의 전역 함수·변수를 자유롭게 참조한다.

## 테스트용 더미 데이터

`dev-seed/daegu-kumoh-templates.js`는 대구에서 금오공과대학교(구미)로 통학하는 경로를
가정한 템플릿 3종(왕복/등교 편도/하교 편도)을 만드는 개발용 스크립트다. `index.html`에는
연결되어 있지 않으므로, 필요할 때 브라우저 개발자 도구(F12) → Console 탭에 파일 내용을
직접 붙여넣어 실행한다. 자세한 절차와 주의사항은 파일 상단 주석을 참고할 것.

## 알려진 제한사항

- 별도 백업/내보내기 기능 없음 — 브라우저 데이터(LocalStorage)를 지우면 복구 불가
- 다중 사용자·로그인 미지원 (설계서 범위 제외)
- 지역·요금 데이터를 코드(`fareModule.js`의 `DEFAULT_FARE_DATA`)에 직접 추가해야 하며,
  이미 LocalStorage에 저장된 사용자는 새 지역이 자동 반영되지 않는다(초기화 필요)
