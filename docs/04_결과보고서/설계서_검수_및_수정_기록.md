# 설계서 검수 및 수정 기록

결과보고서 작성용 기초 자료. 구현을 마친 뒤 설계서 v1.6과 실제 코드를 대조해 검수하고,
발견한 문제를 수정한 과정을 정리한다.

| 항목 | 내용 |
|---|---|
| 기간 | 2026-09-23 ~ 2026-09-29 |
| 검수 기준 | 소프트웨어 설계서 v1.6 (`docs/03_설계서`), 기획 및 요구사항 정의서 (`docs/02_제안서`) |
| 검수 방법 | 설계서 본문·표·목업(그림 5~8)과 코드 대조, Node.js로 모듈 단독 실행, 브라우저에서 화면 조작 및 저장 실패 강제 주입 |
| 작업 방식 | Claude(AI)가 검수·수정·검증을 수행하고, 작성자가 우선순위와 구현 방향(범위 축소 vs 구현 등)을 결정 |

### 1.3 우선순위 결정 근거

작업 순서는 "설계서 10장 테스트에서 바로 실패하는가 / 데이터가 사라질 수 있는가 → 설계서에 명시된 기능 누락 → 비기능·문서 정합성" 기준으로 정했다.

| 우선순위 | 항목 | 이유 |
|---|---|---|
| P1 | 1, 2, 3 | 10장 "저장 중 강제 오류 주입 테스트"·"임의 입력 테스트"에서 즉시 실패, 데이터 손실 가능 |
| P2 | 4, 5, 6 | 설계서·제안서에 명시된 기능 누락 |
| P3 | 7, 8 | 비기능 요구사항(유지보수성·안정성) |

6번은 설계서 내부에서 서술이 엇갈렸다(4.1·4.2·5.2에는 직접 입력이 있으나 3.3 흐름·7.1 화면 목록·그림 7 목업에는 없음). 범위를 줄이는 안과 구현하는 안을 비교한 뒤, 제안서 FR-03에 명시된 요구사항이라는 점을 근거로 구현하기로 결정했다.

- 1월 1일 00:30 내역(UTC로는 전년도 12월 31일)이 "올해"에 포함되는지 → 포함됨 (로컬 시간 기준 비교)

## 4. 남은 제한사항

설계 범위상 구현하지 않았거나 알려진 제약.

- 백업/내보내기 기능 없음: 브라우저 데이터를 지우면 복구 불가 (설계서 5.3·9.2에서 범위 제외로 명시)
- 새 지역을 코드에 추가해도, 이미 요금 데이터가 저장된 브라우저에는 자동 반영되지 않음 (초기화 필요). 이때 해당 지역 내역은 0원·"요금 정보 없음"으로 표시됨
- 사용 내역 수정은 노선명·구분·환승만 가능 (지역·요금등급은 수정 불가)
- 직접 등록의 등록 시각은 버튼을 누른 시각으로 고정 (지난 이동을 과거 시각으로 기록하는 기능 없음)
- 저장 실패 시 별도 팝업 없이 화면 안내 문구·콘솔 로그로만 알림 (설계서 9.2 방침)
